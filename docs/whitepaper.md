## 1. Abstract

Every second, billions of people around the world consume internet data. They stream videos, browse social media, use AI assistants, play online games, shop on e-commerce platforms, and communicate through messaging apps. In every one of these interactions, the user generates economic value — for the service provider, for the advertiser, for the network carrier — yet the user, the very source of that value, receives nothing in return.

**NetReward** fundamentally reverses this equation.

NetReward is a blockchain-powered data-rewards ecosystem that compensates internet users with **NRT (NetReward Token)** for their everyday data consumption. Built on the Solana blockchain for speed and cost-efficiency, NRT is not a speculative asset — it is a **core functional utility token** that bridges the worlds of data, artificial intelligence, and decentralized finance. Users earn NRT passively by using the internet. Service Providers fund campaigns to acquire and retain users. Internet Service Providers earn cashback revenue on every byte of data flowing through their networks. Investors gain exposure to the fastest-growing asset class on earth: the global data economy.

**Tagline:** *"Your Data, Your Rewards, Your Power."*

## 2. The Problem: A Broken Internet Economy

### 2.1 For Users: Data Poverty
In emerging economies across Africa, Southeast Asia, and Latin America, the cost of 1GB of mobile data can represent 5–10% of average daily income. This creates a "data poverty" trap: users cannot afford to access digital education, financial services, telemedicine, or employment platforms. Even in developed markets, consumers pay hundreds of dollars annually for internet services while generating billions of dollars in value for tech companies through their attention and data — without receiving any share of that value.

### 2.2 For Service Providers: Wasted Marketing Spend
Traditional digital advertising is broken. The average click-through rate on display advertising is 0.1%. Service Providers — streaming platforms, e-commerce marketplaces, fintech apps, SaaS products, and gaming studios — spend billions annually on ads that do not convert. Users ignore banner ads, skip pre-roll videos, and install ad blockers. The cost of acquiring a single customer (CAC) continues to rise, while the return on advertising spend (ROAS) continues to fall. There is no mechanism to directly reward a user for genuinely engaging with a service.

### 2.3 For ISPs: Stagnating Revenue
Telecommunications companies and internet service providers face brutal price competition in the consumer market. Average Revenue Per User (ARPU) is declining globally. ISPs are commodity providers — they carry data, but they have no relationship with the value created on top of their networks. They need new B2B revenue models that leverage their infrastructure without requiring massive capital expenditure.

### 2.4 For Governments: Digital Exclusion
Governments worldwide are investing in digital public infrastructure — digital identity, digital banking, e-governance, online education — but adoption is throttled by the cost of connectivity. The digital divide is not just an infrastructure problem; it is an affordability problem. Governments need mechanisms that incentivize internet adoption without requiring direct subsidies.

**The core mechanism:**
1. **Service Providers** create reward campaigns, depositing fiat or NRT into escrow.
2. **Users** join campaigns and use the SP's service (streaming, shopping, gaming, AI tools).
3. **NetReward's telemetry engine** passively tracks the bandwidth consumed — not the content, only the volume of data in bytes — using cryptographically signed, privacy-preserving SDKs.
4. **The Reward Engine** calculates NRT earnings using the formula:
   ```
   NRT Earned = (Total Bytes / 1 GB) × Base Reward Rate × NHS Multiplier × Campaign Bonus
   ```
5. **Distribution** is automatic and instant:
   - **85%** goes to the **User's** wallet.
   - **10%** goes to the **Service Provider** as infrastructure cashback.
   - **5%** goes to the **Internet Service Provider** whose network carried the data.
6. The user can **spend NRT** on subscriptions, trade it on P2P marketplaces, redeem it for local fiat currency, or hold it as a growing asset.

## 4. How It Works: The Complete Process Flow

### 4.1 User Journey
1. **Download** the NetReward app (iOS/Android) or install the browser extension (Chrome/Edge).
2. **Register** with email and password. Select role: User, SP, or ISP.
3. **Browse Campaigns** — see which services are offering NRT rewards.
4. **Join a Campaign** — one tap to opt in.
5. **Use the Internet Normally** — stream Netflix, shop on Jumia, chat on WhatsApp, play Fortnite, use ChatGPT. The NetReward SDK runs silently in the background.
6. **Watch NRT accumulate** in real-time on the dashboard — an animated live counter shows earnings as they happen.
7. **Spend or Save** — withdraw NRT as naira, dollars, or any local currency; spend on subscriptions; trade on the P2P marketplace; or hold for appreciation.

### 4.2 Service Provider Journey
1. **Register as SP** and complete business KYC (logo, website, business registration document).
2. **Register a Service** — provide app name, category (streaming, e-commerce, gaming, fintech, AI, social media, productivity, education), web domain, Android package name, iOS bundle ID, and webhook URL.
3. **Integrate the NetReward Tracker SDK** into the SP's app or website. The SDK is available for JavaScript (NPM), Android (AAR), iOS (Swift Package), and Windows (NuGet). Integration is typically 3 lines of code.
4. **Create a Campaign** — define budget, target demographics, locations, dates, and reward rates.
5. **Fund the Campaign** — deposit NRT into the campaign escrow. The campaign goes live when funded.
6. **Receive 10% cashback** — for every NRT distributed to users via the SP's campaign, 10% is automatically credited back to the SP's wallet to help offset infrastructure costs.
7. **Monitor analytics** — real-time dashboards showing users reached, NRT distributed, session lengths, ROI, and conversion funnels.

### 4.3 ISP Journey
1. **Register as ISP** and complete business KYC (ISP license, business registration, logo).
2. **Register a Network** — provide network name, category (Telecom, Satellite, Fiber, Mobile, Broadband), country, ASN (Autonomous System Number), IP ranges (CIDR blocks), handshake URL, and webhook URL.
3. **Verification** — NetReward verifies the ISP's ASN ownership via BGP challenge-response and RIPE/ARIN validation.
4. **Passive Revenue** — once verified, the ISP does nothing. Whenever a user's device IP falls within the ISP's registered network ranges, 5% of all NRT earned by that user is automatically credited to the ISP's wallet. There is no SDK to integrate — revenue is location-based and fully automatic.
5. **Create ISP Campaigns** (optional) — ISPs can create bonus reward campaigns for users on their network, incentivizing data subscriptions and network loyalty.
6. **Monitor analytics** — dashboards showing total customers, data consumed, campaigns, 5% cashback earnings, and network signal quality.

| **CDN** | Cloudflare | DDoS protection, global edge caching, WAF |

### 21.2 Security Architecture

| Security Layer | Implementation |
|---------------|---------------|
| **Telemetry Signing** | Every bandwidth report is HMAC-SHA256 signed. Unsigned or tampered reports are rejected. |
| **Device Fingerprinting** | Hardware-level unique identifiers prevent Sybil attacks (multiple fake accounts). |
| **Anomaly Detection** | Real-time heuristic analysis flags impossible speeds (e.g., 10 GB in 5 seconds), impossible durations, and volume spikes. |
| **JWT Authentication** | Short-lived access tokens (15 min) with rotating refresh tokens (7 days). |
| **Biometric Auth** | Face ID and fingerprint login on mobile devices. |
| **KYC & AML** | Tiered identity verification with liveness checks and document validation. |
| **Multi-Sig Treasury** | 3-of-5 multi-signature wallet (Squads Protocol) for all treasury operations. |
| **RLS Policies** | Row-Level Security on all database tables ensuring users can only access their own data. |
| **Audit Logging** | Every admin action, wallet mutation, and security event is logged with IP, user agent, and timestamp. |
| **Emergency Controls** | Token freeze, maintenance mode, user suspension, and IP blocking — all available with one-click admin toggles. |

### 21.3 Anti-Fraud Pipeline

```
Raw Telemetry Event
  → HMAC Signature Verification ✓
  → Session ID Deduplication (Redis, 24hr TTL) ✓
  → Volume Anomaly Check (> 100 GB/session → flagged) ✓
  → Speed Anomaly Check (rate > physical network capacity → flagged) ✓
  → Cross-Reference (SDK vs. TrafficStats within 20% tolerance) ✓
  → Campaign Budget Check (atomic decrement, no over-spend) ✓
  → ISP Correlation (validate against ISP data flow reports) ✓
  → REWARD ✓ or → Admin Anomaly Queue for manual review
```
